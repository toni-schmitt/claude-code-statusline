# Status line previews

Everything in `docs/previews/` is generated by this directory. No image is
drawn by hand: each one is the real stdout of `out/ember` or
`out/ember-subagent`, rendered by a real terminal emulator and screenshotted.

## How it works

1. **`generate.py`** builds one throwaway sandbox per frame — `$HOME`,
   `$CLAUDE_CONFIG_DIR` and `$TMPDIR` all redirected, a fake git repo for the
   branch — then pipes a synthetic Claude Code stdin payload (§3's contract)
   into the real binary and keeps its ANSI output in `build/ansi/`. Your own
   config, state file and usage cache are never read or written.

   States that depend on accumulated state are produced the way they arise in
   life, by replaying a short sequence of payloads through one sandbox: a
   prior session contributes the rest of the day's spend, and the current
   session is seen once at a lower 5h reading (which sets its watermark)
   before the frame that gets kept. The credits states seed the refresher
   cache with the usage API's `used_credits` at each step, so the session and
   daily deltas are computed by the binary, not written by hand.

2. **`capture.py`** screenshots each frame with [VHS](https://github.com/charmbracelet/vhs),
   which drives `ttyd` plus a headless browser — the rendering is done by
   xterm.js, an actual terminal emulator. Frames are shot at 48px (2x) so they
   stay sharp on retina displays; the README shows them at half width.

3. **`pngtrim.py`** crops the result to the content, and pads frames with the
   same line count to a common height so a gallery section doesn't jitter. The terminal is sized
   larger than the content on purpose — a last line that exactly fills the
   width would wrap-scroll the first line off the top — and xterm centres
   whatever grid it ends up with, so the slack is found by looking for the ink
   rather than by arithmetic. `pngmeasure.py` is the minimal PNG reader both
   use (no Pillow, no dependencies).

## Regenerating

```sh
dotnet publish -c Release -r <RID> -p:PublishAot=true src/Ember/Ember.csproj -o out
dotnet publish -c Release -r <RID> -p:PublishAot=true src/Ember.Subagent/Ember.Subagent.csproj -o out

python3 tools/preview/generate.py        # binaries -> build/ansi/*.ansi
python3 tools/preview/capture.py         # ansi     -> build/png/*.png
python3 tools/preview/capture.py --chrome hero-statusline hero-with-subagent-rows
python3 tools/preview/publish.py         # normalise heights, copy to docs/previews/
python3 tools/preview/update_readme.py   # splice the gallery into README.md
```

`generate.py` and `capture.py` both take frame names, so one group can be
redone on its own:

```sh
python3 tools/preview/generate.py width-93-columns width-83-columns
python3 tools/preview/capture.py  width-93-columns width-83-columns
```

`build/` is gitignored; only the copies under `docs/previews/` are committed.
`update_readme.py` is idempotent — it replaces the hero and the whole "What it
looks like" section, so it is safe to re-run after every capture.

Frames are shot at 28px type, which lands them at roughly 1800px wide for the
~900px slot the README displays them in: 2x for retina, and no resolution
beyond what a screen can use.

## Two things that will bite you

- **VHS 0.12.0 is broken**: it records the frames, then exits 0 having written
  nothing at all, because a cancelled context kills the encode step
  ([vhs#787](https://github.com/charmbracelet/vhs/issues/787)). Use 0.11.0:
  `GOBIN=$PWD/tools/preview/build/bin go install github.com/charmbracelet/vhs@v0.11.0`.
  `capture.py` runs that local copy, not whatever is on `PATH`.
- **VHS finds a browser by name.** With Chromium rather than Google Chrome
  installed, put an exec wrapper (not a symlink — that breaks Chromium's
  framework lookup) named `chromium` in `build/bin`:

  ```sh
  printf '#!/bin/sh\nexec "/Applications/Chromium.app/Contents/MacOS/Chromium" "$@"\n' \
    > tools/preview/build/bin/chromium && chmod +x tools/preview/build/bin/chromium
  ```

A `Screenshot` as the last command of a tape is sometimes dropped
([vhs#540](https://github.com/charmbracelet/vhs/issues/540)); every generated
tape therefore ends with a trailing `Sleep`.
